# Project Context — jpmx-pro

## 1. Purpose, scope, and source of truth

`jpmx-pro` is Joe Palomino's bilingual Product Design portfolio. It presents portfolio work, an about page, service information, contact entry points, and selected case studies in Spanish and English.

This document is a concise technical and product-context reference for future work. It describes the repository as observed in source control. [AGENTS.md](../AGENTS.md) is the source of truth for Codex operating rules; this document does not repeat those rules. [README.md](../README.md) remains the setup and operational entry point.

## 2. System overview

The site is a static Astro application. Page components read validated JSON content through Astro Content Collections, generate static routes at build time, and write the production output to `dist/`.

GitHub is the configured repository and content backend. Decap CMS is served at `/admin` and is configured to write editorial changes to `main` through GitHub OAuth Pages Functions. The repository documents Cloudflare Pages as the hosting and build service.

## 3. Technology and runtime

- Astro 7 with static output, directory-formatted builds, and sitemap generation.
- TypeScript with Astro's strict configuration.
- Node.js 24 and npm; `npm run build` runs `astro check` followed by the production build.
- React for the `ContactGradient` interactive island; Astro is used for static page and component composition.
- Astro Content Collections, JSON files, and Zod schemas for content validation.
- GSAP, Lottie, Three.js, GradFlow, and Hugeicons for interactions, motion, WebGL, gradients, and icons.
- Decap CMS, Cloudflare Pages Functions, and GitHub OAuth for editorial administration.
- Sharp for the image-optimization script.

Exact dependency versions and scripts are defined in [package.json](../package.json). Site configuration is in [astro.config.mjs](../astro.config.mjs).

## 5. Routes and page composition

| Route | Purpose | Composition |
| --- | --- | --- |
| `/` and `/en/` | Spanish and English home pages. | `HomePage` with shared header, footer, hero, projects, services, and statistics. |
| `/about` and `/en/about` | About pages. | `AboutPage` with content-driven copy and static imagery. |
| `/projects/[slug]` and `/en/projects/[slug]` | Published case studies. | `ProjectPage`, generated only for non-draft projects of the matching locale. |
| `/admin` | Decap CMS shell. | Loads and initializes Decap CMS. |
| `/404` | Static not-found page. | Dedicated Astro route. |

[BaseLayout.astro](../src/layouts/BaseLayout.astro) provides shared metadata, canonical URLs, alternate-language links, Open Graph data, fonts, global reveal behavior, and the cursor layers. The configured sitemap excludes `/admin` and the 404 route.

## 6. Content model and bilingual behavior

The content contract is defined in [src/content.config.ts](../src/content.config.ts). It exposes two collections:

- `pages`: one localized home JSON entry per locale in `src/content/pages/{es,en}/home.json`.
- `projects`: localized project JSON entries in `src/content/projects/{es,en}/` with shared slugs and fields for metadata, case-study sections, images, related work, order, and draft status.

Route generation filters projects with `draft: true`; only published projects receive case-study pages and sitemap entries. Home-page previews follow a separate selection: `getHomepageProjects()` currently selects Afore Móvil, Calimax, and Dina without filtering `draft`. `ProjectCard` renders a selected draft as a non-linking article, so Dina currently appears as a preview without a public detail route. Pet Love Story is a draft but is not part of that home-page preview selection. Locale-specific page routes and `hreflang` links are generated by the page entry points and `BaseLayout`.

New UI strings and content structures must remain equivalent across Spanish and English. Content changes must remain compatible with both the Zod schemas and the Decap CMS form configuration.

Each home-page service contains a localized title, short description, and skill list. `HomePage` renders the skills as visual pills; Decap CMS exposes the section description and all three service fields for both locales.

## 7. Components, interactions, and visual system

The principal page components are [HomePage.astro](../src/components/HomePage.astro), [AboutPage.astro](../src/components/AboutPage.astro), and [ProjectPage.astro](../src/components/ProjectPage.astro). [Header.astro](../src/components/Header.astro) provides desktop and accessible mobile navigation; [Footer.astro](../src/components/Footer.astro) provides contact content and the contact gradient.

The home page includes a GSAP ScrambleText entrance for the hero role, GSAP project-card reveals, a rotating availability message, a Lottie scroll cue, service cards with a bottom-to-top hover fill, and project/statistics marquees that react to scroll direction. `CustomCursor` supplies pointer states for fine pointers. In `main`, `FluidCursor` mounts the Three.js-based fluid background simulation and responds to mouse/pen movement, background clicks, deliberate touch taps, and passive touch-drag trails that preserve native page scrolling. `ContactGradient` is a visible-on-demand React island powered by GradFlow.

Motion code checks reduced-motion preferences where implemented. Shared visual language, responsive layout, typography, and component styling live primarily in [src/styles/global.css](../src/styles/global.css).

## 8. CMS, assets, and editorial workflow

[public/admin/config.yml](../public/admin/config.yml) configures Decap CMS with the GitHub backend, repository `joewildem/jpmx-pro`, branch `main`, and Spanish/English folder-based localization. It manages the home-page entries and project JSON files.

The CMS OAuth flow is implemented by [functions/api/auth.js](../functions/api/auth.js) and [functions/api/callback.js](../functions/api/callback.js). Required runtime values are documented in the README but are not stored in this repository.

Original project media is stored in `public/uploads/`; optimized WebP assets are in `public/images/`. `npm run images` runs [scripts/optimize-images.mjs](../scripts/optimize-images.mjs). The downloadable résumé is stored in `public/documents/`.

## 9. GitHub and Cloudflare Pages delivery

The configured Git remote is `https://github.com/joewildem/jpmx-pro.git`. The README documents `main` as the Cloudflare Pages production branch, with `npm run build`, `dist/` output, Node 24, and `jpmx.pro` as the primary domain.

Cloudflare Pages Functions are supplied through `functions/api/`. [public/_headers](../public/_headers) defines repository-managed response headers, including CMS-specific cache and content-security policies. [public/robots.txt](../public/robots.txt) declares the sitemap location.

The actual Pages project, deployment history, domains, environment-variable values, Cloudflare Access policy, preview settings, and GitHub branch-protection/check settings are external configuration and must be verified in their respective dashboards.

## 10. Architectural and product decisions to preserve

- Keep the site statically generated and content-driven unless a requested capability requires a different model.
- Treat the Zod schemas, bilingual folder layout, and Decap configuration as a coordinated content contract.
- Prefer Astro components for static presentation; keep React limited to client-side islands that need it.
- Preserve the editorial layout, bilingual SEO metadata, and responsive interaction design.
- Preserve the existing visual effects as intentional product behavior while respecting reduced motion and device capability checks.
- Keep credentials and runtime secrets outside the repository.
- Keep project resources, licenses, and references recorded in [docs/recursos.md](recursos.md).

## 11. Current capabilities and known limitations

### Confirmed capabilities

- The current content inventory contains published Afore Móvil and Calimax case studies in both locales.
- Dina and Pet Love Story exist in both locales as drafts.
- The site includes static SEO metadata, canonical URLs, alternate-language links, a sitemap, a CMS shell, and GitHub OAuth Functions.

### Diagnostic snapshot — 2026-10-22

- `getHomepageProjects()` selects `dina` for the home-page preview list without filtering `draft`. `ProjectCard` renders draft entries as non-linking articles. This differs from the README's broader statement that drafts do not appear publicly and should be clarified before changing draft behavior.
- The fluid background supports mouse/pen movement, non-interactive background clicks, deliberate touch taps, and passive touch-drag trails in `main`. Touch input initializes WebGL on the first eligible contact, uses a reduced simulation profile, preserves native scrolling, and ignores gestures that begin on interactive controls.
- The `pages` Zod schema and Decap home-page form both expose `servicesDescription` plus each service title, description, and skill list.
- No automated test suite is tracked. The GitHub Actions `Quality` workflow runs `npm ci` and `npm run build` for pull requests to `main` and pushes to `main`; external branch enforcement remains dashboard configuration that cannot be verified from the repository.
- Bundle-size and third-party dependency warnings should be evaluated separately; they are not resolved by this document.
